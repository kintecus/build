## Phase 1.2A - Geo-enabled audiences

### Done when

- ETL pipeline reads ZIP-level data from ClickHouse and unloads Parquet files with `geoip_code` populated
- Forecast Service filters eligible assets using ZIP as an additional dimension (geo-fuelled audience scores applied at query time)
- Audience score joins include ZIP field; threshold remains 0.6 (configurable)
- API V1 contract preserved - no breaking changes; ZIP is an internal filter, not exposed as new required input
- First full deployment cycle completed: dev → (optional) staging → prod
- Latency target met: <5s end-to-end on representative dataset (up to 10s acceptable with justification)
- CH ETL PR reviewed and approved by CLIENT-DS-LEAD; API PR reviewed and approved by CLIENT-PRODUCT-MGR

Status as of Feb 23: Forecast Service PR (ENG-LEAD/ENG-2) targeting CLIENT-DS-LEAD review by EOD. ENG-1's initial RS→CH refactoring PR still in CLIENT-DS-LEAD's review - ZIP ETL is a separate branch, not yet submitted. Both need to land before Feb 25 weekly sync. Risk: ENG-1 can't commit to timeline.

### Success metrics

1. **Forecasting accuracy** - *X% increase in accuracy*, compared to pre-zip solution, *Y% increase in forecast availability* for previously blocked campaign parameters. Evals based on historical campaign data - the "offline" process on AdScale's current MPT architecture diagram.
2. **Latency p95 <5s** - 95th percentile end-to-end response time on production traffic stays under 5s (10s hard ceiling). Measured from existing API request logs.
3. **ZIP coverage >95%** - ≥95% of delivery dataset rows have non-null `geoip_code` after ETL migration. Verified from Parquet output counts.
4. **Zero API contract breaks** - existing integration test suite passes with 0 failures post-deploy.
5. **Audience score match rate ≥98%** - ≥98% of assets that had audience scores pre-ZIP continue to receive scores post-ZIP. Validates no silent data loss from the join expansion.
6. **Deployment cycle <5 business days** - first full dev → staging → prod cycle completes within 5 business days of PR merge.

## Phase 1.2B - Model integration

**Done when:**

- Data from all four KPI models loaded from the model predictions data feed, and integrated into the forecast pipeline:
- Impression rate (= win rate; note: includes extra `responded_price` dimension)
- CTR
- VCR (video completion rate; formerly VTR)
- Viewability
- API returns model-backed CPM-to-impression curves with all four KPIs per placement, replacing any placeholder logic
- Validation passed: ENG-1 provides 1 day of production data with ZIPs; ENG-2 confirms forecasts based on new data match expected output (no regression from placeholder values)
- No MPT<>FE changes owned by Northwind - frontend/UI is AdScale One's responsibility per scope agreement. However, the 1.3 API contract (what AdScale One must call) depends on the unresolved UX gate decision (gate 3: multi-add vs. combined audience). *(Confidence: high on ownership, gate 3 still open)*
- Done means deployed to prod, not just ready - consistent with 1.2A DoD ("first full deployment cycle completed: dev → staging → prod"). *(Confidence: medium - worth explicit confirmation with CLIENT-DS-LEAD/CLIENT-PRODUCT)*

**Schema (confirmed Feb 19 by CLIENT-DS-LEAD):**

- CTR, VCR, Viewability: `geoip_code`, `environment_type`, `ad_unit_type`, `device_computed_type`, `predicted_value`
- Impression rate: same + `responded_price` ($0.0005-$0.03 bid = $0.50-$30.00 CPM); 878,400 rows vs. 14,640 for the others

**Success metrics:**

1. **Model coverage 100%** - all four KPI fields return model-backed values (not nulls or placeholders) for every valid placement tuple in the response. Verified against CLIENT-DS-LEAD's CSV row counts.
2. **Prediction lookup latency <200ms** - model CSV lookup adds <200ms to the request path at p95. Measured from API request logs.
3. **Forecast output consistency** - for a fixed input, forecast output variance <1% between consecutive runs (deterministic pipeline). Validated by ENG-2 against ENG-1's production data sample.
4. **No regression on 1.2A metrics** - latency p95, audience score match rate, and zero API contract breaks (integration test suite passes) remain within 1.2A thresholds post-deploy. *(TBD resolved: "zero API contract breaks" is the most meaningful third metric to guard here - the one 1.2B model lookup changes could silently break. Confidence: medium)*
5. **Model freshness** - API serves model predictions from CSVs updated within the last 30 days. Verified by checking CSV file timestamps in S3; staleness alert fires and is observable in production monitoring if the 30-day threshold is exceeded.

## Phase 1.3 - Audience broadening (recommender)

Two tiers: what Northwind ships regardless, and what depends on AdScale delivering inputs by Feb 28.

**Success metrics:**

1. **SC-001: ≥80% recommendation yield** - ≥80% of narrow detections with an audience produce at least one recommendation with higher estimated inventory. Acceptance gate defined in CLIENT-PRODUCT's audience-broadening spec; verified by running the acceptance test suite against production traffic samples.
2. **SC-004: 100% brand scoping** - zero cross-brand audience leaks in recommendations. Verified by integration test against Brand/Account filter logic.
3. **Narrow detection precision <5% false positive rate** - validated against a manually labeled sample of 50 requests.
4. **Recommendation latency <3s incremental** - recommender adds <3s to total request time vs. baseline forecast at p95. Measured from API logs.
5. **Config update without deploy** - benchmark CPM CSV updates take effect within 1 request cycle with no restart or deploy required. Verified by updating CSV and confirming next request reflects new values.

### Committed scope (Northwind delivers regardless)

- Narrow audience detection triggers correctly:
- CPM exceeds country benchmark by >1.5x (configurable)
- OR achievable budget <50% of requested budget (configurable)
- Both conditions trigger independently
- Audience recommendations returned for all audience types:
- Basic audience → up to 3 ranked alternatives
- Combined audience with AND clauses → single flattened OR expression
- Combined audience, purely OR-based → treated as basic
- No audience in request → warning, no recommendations
- No Brand/Account in request → warning, recommendations omitted with explanation
- **Only already-existing audiences recommended** - no suggestions of combinations that don't yet exist in AdScale's system (3h build latency constraint; new combos are out of scope)
- Recommendations scoped to correct Brand/Account - zero cross-brand leaks
- Benchmark CPM config: CSV, per country, global fallback, updatable without code changes
- Monitoring metrics emitted: narrow detection count, recommendation count, excluded audience count
- API contract documented and ready for AdScale One integration (integration itself is AdScale's responsibility)
- Acceptance gates from CLIENT-PRODUCT's spec:
- SC-001: ≥80% of narrow detections with audience yield a recommendation with higher estimated inventory
- SC-004: 100% of recommendations scoped to correct Brand/Account

### Conditional scope (requires AdScale to deliver by Feb 28)

In scope **only if** AdScale confirms and delivers prerequisites by Feb 28. If they slip, CLIENT-PRODUCT decides - ship without them, descope 1.3, or move the deadline. His call to document.

| Feature | Prerequisite | Owner |
|---|---|---|
| Cosine similarity ranking (audience manifesto embeddings) | Embedding service access + audience metadata pipeline staged | Audience team (CLIENT-VP-DS/CLIENT-PERSONA-LEAD) |

If embedding service is not accessible by Mar 5: recommender ships with impression-volume uplift as the sole ranking signal. The recommender remains functional - impression-volume uplift is a valid ranking signal; semantic similarity is an enhancement, not a requirement for Phase 1 value.

## Transparency funnel - not in Phase 1 scope

CLIENT-PRODUCT's second spec is context and future direction. Not building in Phase 1.

**Design note for phase 1.3**: the forecast pipeline should support parameterized filter levels (country only / country+filters / country+filters+audience). This is required for Audience Broadening and directly enables Transparency Funnel as a low-effort add in future phases.

**When we do build it (Phase 2):**

- 3-stage impression funnel (global → filtering → filtering+audience) on every forecast response
- Additive response field, backward compatible
- Up to 3 parallel pipeline calls, 15s max latency
- Main forecast result reused for matching stage (saves one pipeline call)
