## Andon cord

### Production incident: Forecast Service down (Mar 5)

Two 5xx spikes on Mar 5. Root cause: schema drift in prod S3 Parquet files - ETL runs on different days produced mismatched column types (`nb_impressions`: Int64 vs Decimal(38,1)). Polars' `scan_parquet` inferred schema from the first file and choked when merging files with different types.

**Timeline:**

| Time (CET) | Event |
|-------------|-------|
| 10:20 | Errors start in Datadog, correlated with new-release Airflow DAG run |
| 10:58 | CLIENT-PRODUCT-MGR reports Forecast Service down |
| 12:06 | CLIENT-DS-LEAD confirms root cause correlation, rolls back to v0.21.1 |
| 12:33 | ENG-1 opens PR #116: explicit Polars schemas for S3 parquet reads |
| 14:50 | PR #116 merged and deployed. Service restored briefly. |
| 17:04 | Error recurs. Same schema mismatch. CLIENT-DS-LEAD reports 11 errors in 5 min. |
| 17:17 | CLIENT-DS-LEAD rolls back to v0.21.1 again. Service restored. |
| 19:00 | CLIENT-DS-LEAD confirms no Friday releases (AdScale policy). Deploy moves to Monday. |

**Current state:** Prod stable on v0.21.1 rollback. Fix (PR #116) in master, reviewed by CLIENT-DS-LEAD with SonarCloud feedback. ENG-1 addressing comments. Monday morning deploy confirmed.

**Why it wasn't caught earlier:** STAGING has no historical data, so schema drift only shows up when reading files from different ETL versions side by side. No schema contract between ETL and API. No smoke test against prod S3 paths.

**Prevention:**
1. Schema validation on ETL write side - enforce explicit column types, fail loud on mismatch
2. Pre-deploy smoke test against prod S3 (PR #116 includes `scripts/check_prod_parquets.py`)
3. STAGING sandbox with prod data (approved Mar 4 - would have caught this)

**Side finding:** CLIENT-DS-LEAD flagged that forecasting errors are logged as `info` instead of `error` in Datadog. Separate fix needed.
